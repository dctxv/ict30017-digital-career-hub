One question drove everything: when this is cloned onto a machine nobody on
the team has touched, what happens? The answer, before this session, was that
the server printed `Server running` and then the first click on any AI
feature said "Analysis failed" — and the log said `400 status code (no body)`.

---

## 1. Every provider failure was invisible

Google AI Studio returns its error body as a JSON *array* — `[{ "error":
{...} }]` — and the `openai` SDK reads `body.error`, which an array does not
have. So the reason ("Please pass a valid API key", "model not found") was
discarded inside the SDK before anything could log it. Every failure, of any
kind, was `400 status code (no body)`.

Fixed in `aiClient.js` with a `fetch` wrapper that unwraps the first element
on error responses only. Nothing about the request path changes; successful
responses are untouched. The SDK's `maxRetries` is also dropped to 1, because
a rejected key was being retried three times before reporting.

## 2. One classifier for the provider

`ai-service/src/utils/aiErrors.js`. Every AI call site — the reviewer's two
paths, `completion.js` (interview and gaps), and the chat route — now returns
or emits one of eight codes instead of throwing:

| Code | HTTP | Cause |
| ---- | ---- | ----- |
| `AI_AUTH` | 502 | Key rejected. Google reports this as a **400**, not 401, so the body is checked |
| `AI_MODEL` | 502 | 404: model closed to this key or misspelled |
| `AI_QUOTA` | 503 | 429 whose body names a per-day quota or billing |
| `AI_BUSY` | 503 | Any other 429 — the per-minute throttle |
| `AI_UNAVAILABLE` | 503 | 5xx |
| `AI_UNREACHABLE` | 503 | No connection at all |
| `AI_BAD_REQUEST` | 502 | 400 that is not a key problem (the `frequency_penalty` class of failure) |
| `AI_ERROR` | 502 | Anything else, detail preserved |

This closes open item 2 from the 27 August notes: `AI_BUSY` no longer tells a
user whose project has spent its daily quota to "try again in a minute".

Each code carries a user sentence (translated to Bangla in
`server/src/i18n/messages.js`) and an operator hint. The server writes two
lines per failure, both starting `[ai-upstream]`: the code, status and
provider detail, then the fix. The client's error screen keys its copy off the
code (`ResumeAnalysisError.jsx`), and the chat widget reads `[ERROR:<code>]`
frames so a configuration failure no longer says "please try again".

Twelve unit tests pin the classifier and the unwrapping, built from the
actual SDK error constructors so they test the shape the SDK really produces.

## 3. A failed review no longer costs a review

The review claims a slot from the daily allowance *before* calling the model.
The interview refunds on failure; the review did not. On a misconfigured
server, three attempts in a minute spent all three daily reviews, and the
fourth attempt — after the fix — was refused as over quota. `refundReview()`
mirrors `refundInterview()` and is called on every AI-failure path in both
review endpoints. Verified live: `used=0` after a rejected-key attempt.

## 4. `npm run check`

`server/scripts/check-setup.js`. Runs the setup steps in README order and
prints PASS / WARN / FAIL with the fix for each: Node version, `.env`
present, each required variable not still a placeholder, model resolution,
database reachable (with a different hint for wrong password, database
missing, and PostgreSQL not running), migrations pending, an admin account
existing, content seeded, and finally one real eight-token request to each
distinct model. `--no-ai` skips the request. Exit code 1 on any FAIL.

The migration order moved to `server/scripts/migrationOrder.js` so the check
and the runner read the same list.

## 5. Smaller things

- `/api/health` now reports `database` and which models are configured, and
  whether a key is set. It still never calls the model.
- `server/.env.example` ships `gemini-3.6-flash` on both tiers, so a fresh
  copy needs only the key and the database password.
- The eight lint errors carried since the UI merge (Node globals in the
  Playwright specs and `vite.config.js`) are fixed in `eslint.config.js`.
  Lint is now clean apart from one pre-existing hooks warning.
- README rewritten as a first-run guide: Windows-first quick start, a
  verification section, first-use notes (admin promotion, password reset
  token in the terminal, daily limits), an explanation of the AI wiring with
  the failure table, every command in one table, troubleshooting keyed on
  the exact messages, and the previous reference material kept at the end.
